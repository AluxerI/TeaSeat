# Конструктор подарков — список и сетка дна

Актуальный `/constructor`: простой список без WebGL и прежняя модель `GiftBox`
в сложном режиме с переходом к редактору дна 2.5D после выбора коробки.
Рабочий поток описан в разделе 9. Разделы 1–8 сохранены как справочник по прежней
сцене `ThreeScene` и компонентам `Stage*`: страница больше их не монтирует.
Их фазовая машина не управляет выбором товара или отправкой запросов.

Документация к `src/components/constructor/`. Написана так, чтобы её можно было
читать без предварительного знания Three.js: сначала термины, потом устройство,
в конце — рецепты «как поменять вот это».

**Запуск:** фронт живёт в докере, `docker start frontend`, страница —
<http://localhost:3000/constructor>. Порт задан в `frontend/vite.config.ts`.

## 1. Термины Three.js

Минимум, которого хватит для чтения этого кода.

### Граф сцены

Всё в 3D — дерево объектов (`Object3D`). У каждого узла свои
`position`, `rotation`, `scale`, и они **наследуются детьми**.

```
scene
└── group            position=[0, 0, 0]     ← «коробка»
    ├── mesh         position=[0, -0.6, 0]  ← дно
    └── group        position=[0, -0.6, 0.75]  ← шарнир стенки
        └── mesh     position=[0, 0.6, 0]      ← сама стенка
```

Если повернуть внешнюю группу — повернётся всё вместе. Именно на этом построена
и складывающаяся коробка (поворот шарнира), и полёт в корзину (двигаем корневую
группу, содержимое летит с ней).

| Термин | Что это |
|---|---|
| **Mesh** | Видимый объект = **геометрия** + **материал**. Ничего больше. |
| **Geometry** | Форма: набор вершин. `BoxGeometry(w, h, d)` — коробка, `SphereGeometry`, `TorusGeometry` (бублик), `PlaneGeometry` (плоскость), `CylinderGeometry`. |
| **Material** | Как поверхность реагирует на свет. Мы используем `MeshStandardMaterial` — физически корректный, понимает `roughness`/`metalness` и текстуры. |
| **Group** | Пустой узел, только чтобы объединять детей и трансформировать их вместе. Геометрии нет, не рисуется. |
| **Локальные / мировые координаты** | Локальные — относительно родителя. Мировые — абсолютные. Пакетик, лежащий в коробке, имеет локальную позицию `[-0.44, -0.5, -0.16]`; где он в мире — зависит от того, куда сдвинута коробка. |
| **rotation** | Углы Эйлера в **радианах**, не градусах. `Math.PI / 2` = 90°. Порядок по умолчанию XYZ. |
| **Camera** | `PerspectiveCamera` с полем зрения `fov` (у нас 38° — умеренный «портретный» объектив, меньше искажений, чем у 75°). |
| **Light** | `ambientLight` — равномерная подсветка без направления, `directionalLight` — как солнце, параллельные лучи, умеет тени. |
| **Texture** | Картинка, натянутая на поверхность. |

### Карты текстур

Одна поверхность обычно описана несколькими картами:

| Карта | Что задаёт |
|---|---|
| `map` | **Цвет** (albedo). Просто картинка. |
| `bumpMap` | **Рельеф**. Серая карта высот; светлое = выпуклое. Подделка: геометрия не меняется, меняется только расчёт освещения. Дёшево. |
| `roughnessMap` | **Шероховатость** попиксельно. 0 — зеркало, 1 — матовое. |
| `metalness` | Металл (1) или диэлектрик (0). У фольги 0.72, у картона 0.05. |

`repeat` — сколько раз текстура повторится по поверхности. `wrapS/wrapT = RepeatWrapping` разрешает это повторение.

### Прочее

| Термин | Что это |
|---|---|
| **Shader** | Программа на GLSL, исполняемая на видеокарте. **Вершинный** считает, куда попадёт вершина; **фрагментный** — какого цвета будет пиксель. |
| **Uniform** | Переменная, которую CPU передаёт в шейдер. Одинакова для всех пикселей в вызове. Так работает `uSaturation`. |
| **NDC** | Normalized Device Coordinates: экран в координатах `[-1, 1]` по обеим осям, центр в нуле. Удобно тем, что не зависит от размера канваса. |
| **unproject** | Обратная проекция: из точки экрана получить луч в мире. Так мы находим, куда летит коробка. |
| **Raycasting** | Пускаем луч из курсора в сцену и смотрим, во что он попал. Так работают клики по 3D-объектам. |
| **Draw call** | Одна команда «нарисуй это» видеокарте. Их количество — главный фактор производительности. |
| **Instancing** | Нарисовать одну геометрию N раз за **один** draw call с разными матрицами. 220 чаинок = 1 draw call вместо 220. |
| **Frame loop** | Цикл отрисовки, ~60 раз в секунду. `delta` — секунды с прошлого кадра. |
| **dispose()** | Ручное освобождение памяти на видеокарте. Сборщик мусора JS до неё не достаёт — не вызвал `dispose`, получил утечку. |

### Почему `delta` важна

Наивное сглаживание зависит от частоты кадров:

```ts
// ПЛОХО: на 144 Гц доедет вдвое быстрее, чем на 60 Гц
current += (target - current) * 0.1;

// ХОРОШО: одинаково на любой частоте
current = THREE.MathUtils.damp(current, target, lambda, delta);
```

В коде используется только второй вариант (обёртка `damp` в `anim.ts`).
`lambda` — скорость доезда: 2 — вальяжно, 6 — резко.

## 2. Термины react-three-fiber

r3f — это React-рендерер для Three.js. JSX-теги превращаются в объекты Three.js
по простому правилу: **имя класса с маленькой буквы**.

```tsx
// это JSX…
<mesh position={[0, 1, 0]}>
  <boxGeometry args={[2, 1.2, 1.5]} />
  <meshStandardMaterial color="#c8903c" roughness={0.6} />
</mesh>

// …равносильно этому коду
const mesh = new THREE.Mesh(
  new THREE.BoxGeometry(2, 1.2, 1.5),
  new THREE.MeshStandardMaterial({ color: "#c8903c", roughness: 0.6 })
);
mesh.position.set(0, 1, 0);
```

| Приём | Смысл |
|---|---|
| `args={[...]}` | Аргументы **конструктора**. Меняются только пересозданием объекта. |
| `position` / `rotation` / `scale` | Массив из трёх чисел. |
| `position-y={0.5}` | Точечная установка одного поля. |
| `<primitive object={geo} attach="geometry" />` | Подставить уже созданный объект вместо создания нового. |
| `<Canvas>` | Точка входа: создаёт `WebGLRenderer`, сцену, камеру, запускает цикл кадров. |
| `useFrame((state, delta) => {...})` | Колбэк на каждый кадр. **Здесь и живёт вся анимация.** |
| `useThree(s => s.camera)` | Доступ к камере, рендереру (`gl`), размерам, курсору (`pointer` в NDC). |
| `ref` | Ссылка на созданный `Object3D`. Через неё мутируем трансформ в `useFrame`. |

**drei** — библиотека готовых компонентов: `RoundedBox` (коробка со скруглениями),
`Environment` (карта окружения для отражений), `ContactShadows` (мягкая тень под
объектом), `Lightformer` (светящаяся плоскость).

> ⚠️ У drei есть компоненты, которые **скачивают файлы с CDN**: `Environment`
> с пропом `preset`, `Text` (шрифт), `useGLTF`. Мы их не используем — офлайн у
> PWA от этого ломается. `Environment` **с children** ничего не качает, он
> строит кубмапу из наших `Lightformer`-ов прямо в сцене.

## 4. Три решения, на которых всё держится

### 4.1 Фаза — единственный источник правды

```ts
// sceneConfig.ts
export type ScenePhase =
  | { kind: "chooseType" }              // выбор типа набора
  | { kind: "assembleBox" }             // развёртка складывается
  | { kind: "idleBox" }                 // ждём действий пользователя
  | { kind: "packTea"; slot: 0 | 1 }    // упаковка одного чая
  | { kind: "packSweet" }               // упаковка десерта
  | { kind: "sealAndFly" }              // запечатка и полёт в корзину
  | { kind: "done" };                   // улетел
```

Сцена не знает про «этапы» страницы, кнопки и корзину. Она знает только фазу.
Страница переводит фазы, сцена по завершении скриптового такта зовёт
`onPhaseComplete` — и страница решает, что дальше.

### 4.2 Анимация идёт через мутируемые ref, не через пропсы

Это самое важное для понимания кода. Если бы `fold` был React-пропсом и менялся
каждый кадр — это 60 ререндеров дерева в секунду.

Вместо этого у каждой модели есть **drive** — обычный объект в `useRef`:

```ts
// GiftBox.tsx
export interface BoxDrive {
  fold: number;      // 0 = плоская развёртка, 1 = коробка собрана
  lidLift: number;   // 0 = крышка села, 1 = отведена вверх
  ribbon: number;    // 0..1 затянутость ленты
  bow: number;       // 0..1 бант
  saturation: number; // 0 = ч/б, 1 = цвет
}
```

Режиссёр **пишет** в него внутри своего `useFrame`, модель **читает** в своём:

```tsx
// ThreeScene.tsx — пишем
useFrame(() => {
  boxDrive.current.fold = lerp(0.28, 1, easeInOutCubic(progress));
});

// GiftBox.tsx — читаем
useFrame(() => {
  const fold = drive.current.fold;
  backWallRef.current.rotation.x = lerp(-Math.PI / 2, 0, fold);
});
```

Ререндеров за всю анимацию — **ноль**. Единственное исключение: смена кадра
камеры на такте отлёта, там один `setState` под ref-стражем.

### 4.3 Секвенсор тактов

Хореография «влетел → раскрылся → насыпался → закрылся → упал» спрингом не
выражается. Нужна временная шкала.

```ts
// sceneConfig.ts — длительности в секундах
export const BEATS_TEA = [0.55, 0.6, 1.2, 0.6, 0.7];
export const TEA_BEAT = { flyIn: 0, openFlap: 1, pour: 2, closeFlap: 3, dropIn: 4 };
```

```tsx
const seq = useSequence(BEATS_TEA, phase.kind === "packTea", onDone, phase.slot);

// beatProgress(i): 0 — такт не начался, 1 — прошёл, 0..1 — идёт сейчас
const bOpen  = seq.beatProgress(TEA_BEAT.openFlap);
const bClose = seq.beatProgress(TEA_BEAT.closeFlap);

// клапан открывается на своём такте и закрывается на своём — одной строкой
sachet.flap = clamp01(bOpen - bClose);
```

Два неочевидных момента внутри `useSequence`:

- **`delta` клампится в 0.05 с.** После переключения вкладки браузер отдаёт один
  кадр длиной в несколько секунд — без клампа анимация телепортируется в конец.
- **`resetKey`.** При переходе `packTea{slot:0}` → `packTea{slot:1}` пропс
  `active` не меняется (оба раза `true`), и без отдельного ключа
  последовательность не перезапустилась бы.

## 5. Поток данных

```
ConstructorPage
  │  state: stage, giftType, selectedTeas, selectedSweet
  │  state: phase, packedTeas, packedSweet
  │
  ├──── phase, packedTeas… ────►  ThreeScene (режиссёр)
  │                                 │
  │                                 │  useFrame: фаза + секвенсор → drive.current
  │                                 │
  │                                 ├─► CameraRig      ◄── shot (кадр фазы)
  │                                 ├─► GiftBox        ◄── boxDrive
  │                                 ├─► TeaSachet ×3   ◄── flySachet / restTea0 / restTea1
  │                                 ├─► LeafParticles  ◄── pourDrive
  │                                 └─► SweetItem ×2   ◄── flySweet / restSweet
  │
  ◄──── onPhaseComplete ────────────┘
  │
  └──── stage ────► StageZero / One / Two / Three   (обычный React-UI)
```

### Почему по два экземпляра предметов

Пакетик существует в двух ипостасях:

- **летающий** (`flySachet`) — живёт в **мировых** координатах, отыгрывает
  упаковку рядом с коробкой;
- **уложенный** (`restTea0`, `restTea1`) — **ребёнок коробки**, лежит в слоте.

Ребёнок коробки наследует её трансформ, поэтому при полёте в корзину содержимое
летит вместе с ней автоматически. А летающему это наследование мешало бы —
он должен двигаться независимо.

Переключение — в момент завершения такта укладки: `packedTeas` растёт на 1,
летающий гаснет, уложенный появляется. Чтобы на большом наборе не было скачка
размера, летающему выставляется `scale = boxScale`.

## 6. Разбор модулей

### 6.1 `sceneConfig.ts` — все числа

```ts
// Габариты (мировые единицы; условно 1 ≈ 10 см)
export const BW = 2;        // ширина коробки
export const BH = 1.2;      // высота стенок
```

Кадры камеры — в сферических координатах вокруг точки `target`:

```ts
    radius: 4.2,         // дистанция
    target: [0.15, 0.45, 0],
```

### 6.2 `anim.ts` — математика

**Easing** — функция, искажающая время. На входе `0..1`, на выходе `0..1`, но
«скорость» неравномерна. Линейное движение выглядит механически.

| Функция | Поведение | Где применяется |
|---|---|---|
| `easeInOutCubic` | плавный старт и финиш | сборка коробки, полёт в корзину |
| `easeOutCubic` | быстрый старт, мягкий финиш | почти всё остальное |
| `easeInCubic` | разгон | вертикаль падающих чаинок |
| `easeOutBack` | **перелёт с возвратом** | бант, посадка крышки, подъём стенок |
| `easeOutBounce` | отскок | падение предметов в коробку |

```ts
// «Пружинистость» картона: стенка чуть переходит вертикаль и возвращается
easeOutBack(t, 1.08)
```

**`remap01`** — окно внутри общего прогресса. Так стенки поднимаются внахлёст:

```ts
remap01(v, from, to)  // v<from → 0, v>to → 1, между — 0..1
```

```
fold:  0 ─────────────────────────────────────────► 1
back   ▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░  [0.00 … 0.45]
left   ░░░▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░  [0.12 … 0.60]
right  ░░░░▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░  [0.18 … 0.66]
front  ░░░░░░░▓▓▓▓▓▓▓▓▓▓░░░░░░░░  [0.30 … 0.80]
skirt  ░░░░░░░░░░░▓▓▓▓▓▓▓▓▓░░░░░  [0.50 … 0.88]
park   ░░░░░░░░░░░░░░░░░▓▓▓▓▓▓▓▓  [0.74 … 1.00]
```

Одновременный подъём всех стенок читается механически — лесенка выглядит как
работа рук.

**Дуги.** Предметы летают по квадратичной Безье, а не по прямой:

```ts
arcPoint(out, from, to, lift, t)  // lift — насколько поднять середину
```

Все эти функции пишут результат в переданный `out`-вектор. Это не стилистика:
аллокация нового `Vector3` каждый кадр даёт рывки от сборщика мусора.

### 6.3 `materials.ts` — процедурные текстуры

Внешних файлов нет: всё рисуется в `<canvas>` при первом обращении и кешируется
на уровне модуля.

**Шум.** Многооктавный value-noise на детерминированном ГПСЧ (mulberry32).
Детерминированность принципиальна: со `Math.random()` текстура менялась бы от
загрузки к загрузке, и «поймать» удачный вид при подкрутке было бы невозможно.

Октавы — сложение слоёв разной частоты с убывающей амплитудой:

```
октава 0:  ~~~~~~~~~~~     крупные пятна,     амплитуда 1
октава 1:  ~~~~~~~~~~~     вдвое мельче,      амплитуда 0.5
октава 2:  ~~~~~~~~~~~     ещё вдвое,         амплитуда 0.25
           ─────────────
сумма:     природная неравномерность
```

**Три карты из одной высотной.** Ключевой приём: albedo, `bumpMap` и
`roughnessMap` считаются из одного массива высот, причём roughness **инвертирован**
— впадины бликуют меньше, гребни сильнее. Поэтому рельеф и блики совпадают,
чего не даст независимый шум.

```ts
const shade = 1 - grain * 0.5 + h * grain;   // albedo
const hv = h * 255;                          // bump
const rv = (0.62 + (1 - h) * 0.3) * 255;     // roughness, инвертирован
```

**Тиснение на крышке** — двойной `fillText` со сдвигом: тёмная «канавка» ниже,
светлая «фаска» выше. Плюс тот же текст в высотную карту, чтобы читался в рельефе.

**Фольга** — строчный шум: одно случайное значение на строку, растянутое по X.
Это и даёт характерную «щётку» мятой фольги.

**Обесцвечивание.** Патч фрагментного шейдера через `onBeforeCompile`:

```ts
material.onBeforeCompile = (shader) => {
  shader.uniforms.uSaturation = uniform;
  shader.fragmentShader = shader.fragmentShader
    .replace("void main() {", "uniform float uSaturation;\nvoid main() {")
    .replace("#include <tonemapping_fragment>", `
      {
        float _lum = dot( gl_FragColor.rgb, vec3(0.2126, 0.7152, 0.0722) );
        gl_FragColor.rgb = mix( vec3(_lum), gl_FragColor.rgb, uSaturation );
      }
      #include <tonemapping_fragment>
    `);
};
material.customProgramCacheKey = () => "constructor-saturation";
```

Три момента:
- Врезка **перед тонмаппингом**: освещение уже посчитано, гасим итоговый цвет.
  Если гасить альбедо, на серой коробке останутся золотистые отблески окружения.
- Коэффициенты `0.2126 / 0.7152 / 0.0722` — воспринимаемая яркость (Rec. 709).
  Простое среднее по каналам даёт грязный серый.
- Без своего `customProgramCacheKey` Three переиспользует программу непатченного
  материала, и патч просто не применится.

**Уборка.** `material.dispose()` намеренно не трогает текстуры — они часто общие.
У нас общие лежат в кеше модуля, а копии с индивидуальным `repeat` принадлежат
конкретному материалу. Поэтому есть `disposeMaterial()`, который освобождает
только помеченные `userData.isClone`.

### 6.4 `CameraRig.tsx` — камера

Своя реализация вместо `OrbitControls` из drei. Причина: скриптовая камера и
OrbitControls дерутся за одну и ту же матрицу, и на стыке «пользователь отпустил
мышь → начался такт» получается рывок. Здесь единственный владелец позиции — риг.

Камера всегда на сфере вокруг `target`:

```ts
const sinP = Math.sin(polar);
camera.position.set(
  target.x + radius * sinP * Math.sin(azimuth),
  target.y + radius * Math.cos(polar),
  target.z + radius * sinP * Math.cos(azimuth),
);
camera.lookAt(target);
```

Четыре детали:

- **Углы демпфируются по кратчайшей дуге** (`dampAngle`). Иначе переход через
  `±π` разворачивает камеру «через всю сцену».
- **Дрейф копится отдельно** от азимута. Если добавлять приращение прямо в
  `azimuth`, демпфирование к цели будет его съедать и облёт встанет.
- **Drag — затухающий оффсет** поверх режиссёрского кадра, а не замена ему.
  Отпустил — камера сама возвращается к постановочной точке.
- **Тач-жест забирается условно**: только если горизонтальное смещение превысило
  8 px и доминирует над вертикальным. Вертикаль остаётся странице, палец не
  залипает на сцене. Плюс `touch-action: pan-y` на канвасе в SCSS.

### 6.5 `GiftBox.tsx` — складная коробка

Дно + четыре стенки + крышка с юбкой + лента + бант.

**Шарнир.** Группа стоит в точке поворота, меш внутри смещён на половину высоты
вверх. Поворот группы поднимает стенку как настоящий клапан:

```tsx
<group position={[0, -BH / 2, BD / 2]} rotation={[flatAngle, 0, 0]}>
  <mesh position={[0, BH / 2, 0]} material={materials}>
    <boxGeometry args={[BW, BH, THICK]} />
  </mesh>
</group>
```

Углы разложенного состояния выведены из формул поворота. Для стенки на `z=+BD/2`:
поворот вокруг X на угол θ переводит локальную точку `(0, h, 0)` в
`(0, h·cos θ, h·sin θ)`. При `θ = +π/2` получаем `(0, 0, h)` — стенка лежит
наружу по `+Z`. Отсюда таблица:

| Стенка | Ось | Разложено | Собрано |
|---|---|---|---|
| задняя (`z−`) | X | `−π/2` | `0` |
| передняя (`z+`) | X | `+π/2` | `0` |
| левая (`x−`) | Z | `+π/2` | `0` |
| правая (`x+`) | Z | `−π/2` | `0` |

**Внутри и снаружи — разные материалы.** Это не два меша: у `BoxGeometry` шесть
групп граней в порядке `[+x, −x, +y, −y, +z, −z]`, и в массив материалов можно
подставить нужный в нужный слот.

```ts
const faces = (outerFace: number, innerFace: number) => {
  const arr = [inner, inner, inner, inner, inner, inner];
  arr[outerFace] = outer;   // снаружи золотой картон
  arr[innerFace] = inner;   // внутри тёмный крафт
  return arr;
};
const wallFrontMats = faces(4, 5);  // +z наружу, −z внутрь
```

**Крышка** — не на петлях, а съёмная (как у настоящей подарочной коробки).
`lidLift` управляет: `1` — отведена вверх-назад, `0` — села на корпус.

> `lidLift` **сознательно не обрезается по нулю** — заход в отрицательные
> значения и есть перелёт садящейся крышки, тот самый «пристук». Если поставить
> `clamp01`, крышка будет просто останавливаться.

**Бант** — торы с вырезом (`TorusGeometry(0.17, 0.045, 10, 32, Math.PI * 1.55)`),
а не коробки: скруглённый профиль ловит блики и читается как лента, а
параллелепипеды выглядят планками.

**Содержимое** — `children`, спрятанные за `fold > 0.8`: во время сборки
предметов в коробке ещё быть не должно.

### 6.6 `TeaSachet.tsx` — пакетик

```ts
export interface SachetDrive {
  visible: boolean;
  flap: number;   // 0 закрыт, 1 раскрыт
  fill: number;   // 0 пустой, 1 полный
  position: THREE.Vector3;
  rotation: THREE.Euler;
  scale: number;
}
```

**Наполнение показано раздуванием, а не содержимым** — внутрь всё равно не
видно. Толщина растёт `0.05 → 0.19`, пакетик слегка раздаётся вширь и оседает по
высоте: бумага натягивается. Это то, что глаз действительно считывает.

```ts
bodyRef.current.scale.z = depth / DEPTH_FULL;
bodyRef.current.scale.x = lerp(1, 1.04, fill);  // раздался
bodyRef.current.scale.y = lerp(1, 0.98, fill);  // осел
```

`sachetMouth(drive, out)` возвращает мировую точку горловины — туда целится поток
чаинок.

### 6.7 `LeafParticles.tsx` — поток чаинок

220 частиц в одном `InstancedMesh` = один draw call.

Чаинка — **приплюснутая коробочка** `(0.032, 0.009, 0.019)`, не точка. Точки
(`THREE.Points`) всегда развёрнуты к камере и читаются как пыль; кувыркающиеся
плоскости — как заварка.

Каждая частица летит `FLIGHT_FRACTION = 0.34` от длины такта, старты растянуты
по `(1 − 0.34)` — чтобы последняя успела долететь и струя не обрывалась в воздухе:

```ts
t0: (i / LEAF_COUNT) * (1 - FLIGHT_FRACTION)
const local = (t - leaf.t0) / FLIGHT_FRACTION;   // личное время частицы
```

Разделение осей даёт баллистику:

```ts
const h = easeOutCubic(local);  // горизонталь — гасится
const v = easeInCubic(local);   // вертикаль — разгоняется (падение)
```

Две технические необходимости:

- `frustumCulled={false}` — иначе Three считает область видимости по исходной
  геометрии и меш мигает, когда «формально» уходит за кадр.
- Матрицы обновляются через переиспользуемый `dummy = new THREE.Object3D()`:
  `dummy.updateMatrix()` → `mesh.setMatrixAt(i, dummy.matrix)` →
  `mesh.instanceMatrix.needsUpdate = true`.

Разнотон задаётся один раз через `setColorAt` — в каждом кадре пересчитывать
нечего.

### 6.8 `SweetItem.tsx` — десерт

Обёртка — **две половинки оболочки, съезжающиеся с боков**, а не плоские створки
на шарнирах. Плоский лист нельзя согнуть через ребро; чтобы «завернуть» им плитку,
понадобился бы каскад вложенных шарниров. Две смыкающиеся половинки дают тот же
прочитываемый жест, и в сомкнутом виде это действительно замкнутая фольга.

### 6.9 `Stage0Boxes.tsx` — этап выбора

Коробки показаны **недособранными** (`STAGE0_REST_FOLD = 0.28`). Компромисс:
плоская развёртка не читается как коробка, а готовая коробка не обещает, что её
будут собирать. Наведение доводит до `0.46`, возвращает цвет и кренит модель к
курсору по NDC-позиции указателя.

```ts
const tiltY = hovered ? pointer.x * 0.34 : 0;
const tiltX = hovered ? -pointer.y * 0.2 : 0;
```

**Бесшовная передача** — самая тонкая часть. По клику выбранная коробка едет в
центр с повышенным `λ = 5.5`, а страница ждёт **620 мс** прежде чем переключить
фазу:

```ts
const handleSelectGiftType = useCallback((type: GiftType) => {
  setGiftType(type);
  window.setTimeout(() => setPhase({ kind: "assembleBox" }), 620);
}, []);
```

К этому моменту коробка стоит ровно в центре с тем же `fold` и масштабом, с
которыми стартует `assembleBox`. Объект подменяется (`Stage0Boxes` размонтируется,
монтируется основной `GiftBox`), но геометрия и материалы идентичны — глазом не
ловится.

**Клики ловит прозрачный объём** вокруг коробки, а не сама коробка: между
приподнятыми стенками зияют щели, и луч проходил бы насквозь.

```tsx
<mesh onPointerOver={…} onClick={…}>
  <boxGeometry args={[BW * 1.25, BH * 1.9, BD * 1.25]} />
  <meshBasicMaterial transparent opacity={0} depthWrite={false} />
</mesh>
```

Вращение камеры на этом этапе **выключено**: канвас ловит клики, и протяжка
мышью завершалась бы выбором варианта, которого пользователь не хотел.

### 6.10 `ThreeScene.tsx` — режиссёр

Один большой `switch` по `phase.kind` внутри `useFrame`. Пример такта укладки:

```ts
case "packTea": {
  const bDrop = teaSeq.beatProgress(TEA_BEAT.dropIn);

  if (bDrop > 0) {
    tmpA.set(...STAGING_POS);        // откуда — точка распаковки «на весу»
    tmpB.set(                        // куда — слот в коробке, в мировых координатах
      TEA_SLOTS[slot][0] * boxScale,
      TEA_SLOTS[slot][1] * boxScale,
      TEA_SLOTS[slot][2] * boxScale,
    );

    // Отскок только по вертикали. С отскоком по обеим осям предмет
    // выглядит так, будто ёрзает по столу.
    arcPoint(tmpC, tmpA, tmpB, 0.35, easeOutCubic(bDrop));
    s.position.set(tmpC.x, lerp(tmpA.y, tmpB.y, easeOutBounce(bDrop)), tmpC.z);
    s.rotation.set(lerp(0, -Math.PI / 2, easeOutCubic(bDrop)), 0, tilt);
  }
}
```

**Полёт в корзину.** Иконка живёт в шапке, вне канваса. `domToWorld` переводит её
в мировую точку:

```ts
const ndcX = ((cx - view.left) / view.width) * 2 - 1;
const ndcY = -((cy - view.top) / view.height) * 2 + 1;
out.set(ndcX, ndcY, 0.5).unproject(camera);
// нормализуем луч на постоянную глубину, иначе коробка провалится
// в перспективу непредсказуемо далеко
out.sub(camera.position).normalize().multiplyScalar(distance).add(camera.position);
```

NDC при этом выходят за `[-1, 1]` — это нормально, луч корректен. Цель берётся
**один раз** на старте такта: при скролле она уезжала бы вслед за иконкой.

**Свет:**

```tsx
<ambientLight intensity={0.42} />
<directionalLight position={[4.5, 7, 4]} intensity={1.75} castShadow … />
<directionalLight position={[-4, 3.5, -3]} intensity={0.4} />   {/* заполняющий */}

<Environment resolution={256}>   {/* children → без загрузок с CDN */}
  <Lightformer intensity={2.2} position={[0, 4, 2]} scale={[8, 4, 1]} color="#fffaf0" />
  …
</Environment>

<ContactShadows position={[0, -BH / 2 - THICK - 0.01, 0]} opacity={0.42} … />
```

`ContactShadows` вместо мягких теней — заметно дешевле, а под коробкой разницы
почти не видно.

## 7. Рецепты

### Ускорить или замедлить анимацию

`sceneConfig.ts`, массивы `BEATS_*`. Числа — секунды.

```ts
export const BEATS_TEA = [0.55, 0.6, 1.2, 0.6, 0.7];
//                        влёт  откр  сып  закр  укладка
```

Хочешь дольше сыпать чай — правь третье число. Ничего больше менять не нужно:
секвенсор пересчитает всё сам.

### Переставить камеру

`sceneConfig.ts`, объект `SHOTS`. Соответствие фазам — в `shotForPhase()`.

```ts
packTea: {
  azimuth: 34 * D2R,   // вокруг вертикали; 0 = спереди
  polar: 70 * D2R,     // от зенита; 0 = сверху, 90 = сбоку
  radius: 4.2,         // больше = дальше
  target: [0.15, 0.45, 0],
  lambda: 2,           // 1 = вальяжно, 6 = резко
  drift: 0.04,         // автооблёт, рад/сек; 0 = стоит
}
```

### Изменить размер или пропорции коробки

`BW` / `BH` / `BD` в `sceneConfig.ts`. Всё остальное — шарниры, крышка, лента,
слоты — считается от них.

**Но:** `TEA_SLOTS` и `SWEET_SLOT` задают высоту вручную, потому что предмет
лежит плашмя и вверх у него смотрит **толщина**, а не высота:

```ts
// Пакетик повёрнут на −90° вокруг X ⇒ вверх смотрит DEPTH_FULL ≈ 0.19.
// Подъём над дном = половина толщины (+ немного).
export const TEA_SLOTS = [
  [-0.44, -BH / 2 + 0.1, -0.16],
  [ 0.44, -BH / 2 + 0.1, -0.16],
];
```

Если предметы висят в воздухе или утонули в дне — правь второе число здесь.

### Поменять цвета

`COLORS` в `sceneConfig.ts`. Согласованы с SCSS-токенами страницы
(`$color-accent-light`, `$color-badge`, `$color-success`).

Текстуры кешируются на уровне модуля — после правки нужна перезагрузка страницы,
HMR цвет не подхватит.

### Сделать текстуру грубее или мельче

`materials.ts`, объект `builders`:

```ts
cardboardOuter: () => createCardboard({
  color: COLORS.cardboardOuter,
  seed: 1337,    // другое число = другой рисунок
  grain: 0.34,   // сила зернистости
  fiber: 0.38,   // выраженность волокон
}),
```

Крупность рисунка на поверхности — `repeat` в вызове `buildMaterial`:

```ts
buildMaterial("cardboardOuter", { repeat: 2, bumpScale: 0.014 })
//                                       ↑ больше = мельче рисунок
```

### Добавить новый такт в анимацию

На примере «встряхнуть пакетик перед укладкой»:

1. Добавь длительность и имя индекса в `sceneConfig.ts`:
   ```ts
   export const BEATS_TEA = [0.55, 0.6, 1.2, 0.6, 0.3, 0.7];
   export const TEA_BEAT = {
     flyIn: 0, openFlap: 1, pour: 2, closeFlap: 3,
     shake: 4,        // ← новый
     dropIn: 5,       // ← сдвинулся
   };
   ```
2. Обработай его в `ThreeScene.tsx`, в `case "packTea"`:
   ```ts
   const bShake = teaSeq.beatProgress(TEA_BEAT.shake);
   if (bShake > 0 && bShake < 1) {
     s.rotation.z = Math.sin(bShake * Math.PI * 6) * 0.14;
   }
   ```

Больше нигде править не нужно.

### Добавить новую фазу

1. Вариант в `ScenePhase` (`sceneConfig.ts`).
2. Кадр в `SHOTS` + ветка в `shotForPhase()`.
3. Если фаза скриптовая — добавь `kind` в `SCRIPTED_PHASES`, иначе UI не
   заблокируется и камера останется интерактивной.
4. `BEATS_*` + `useSequence(...)` в `ThreeScene.tsx`.
5. `case` в главном `switch`.
6. Переход в `handlePhaseComplete` (`ConstructorPage.tsx`).

### Добавить новый предмет в коробку

Скопируй `SweetItem.tsx` как образец — он самый простой. Понадобится:

- интерфейс `XxxDrive` + фабрика `createXxxDrive()`;
- `useFrame`, читающий drive и применяющий к refs;
- материалы через `buildMaterial` / `buildPlainMaterial`, освобождение через
  `disposeMaterial` в cleanup;
- **два** экземпляра в `ThreeScene`: летающий (в мировых координатах) и уложенный
  (как `children` у `GiftBox`).

### Убрать 3D целиком, оставив выбор

`ThreeScene` вызывается из `ConstructorPage.tsx` в одном месте, внутри
`.heroStage`. Фазовая машина к нему не привязана: `StageZero/One/Two/Three`
остаются рабочим UI и без сцены. Придётся только звать `handlePhaseComplete`
вручную, потому что сообщать о завершении тактов станет некому.

## 8. Отладка

### Заморозить анимацию на нужном кадре

Самый быстрый способ разглядеть геометрию — подставить константу вместо
секвенсора в `ThreeScene.tsx`:

```ts
case "assembleBox": {
  box.fold = 0.4;   // ← вместо lerp(...) от beatProgress
  break;
}
```

`0` — плоская развёртка, `1` — собранная коробка.

### Проверить, что нет запросов к CDN

DevTools → Network, отфильтровать по домену. Во время работы конструктора
внешних запросов быть не должно. Если появились — почти наверняка кто-то
использовал `Environment preset`, `Text` или `useGLTF` из drei.

### Тени пропали или полосят

У `directionalLight` в `ThreeScene.tsx` границы теневой камеры заданы вручную
(`shadow-camera-left/right/top/bottom = ±6`). Объект вне этих границ тени не
отбрасывает. Полосы (shadow acne) лечатся `shadow-bias` / `shadow-normalBias`.

### Предмет не там, где ожидается

Первым делом проверь, в **чьей** системе координат он живёт. Уложенные предметы —
дети коробки (локальные координаты), летающие — в мировых. Отсюда умножения на
`boxScale` в режиссёре: они переводят локальные слоты в мировые.

### Проверка производительности

`InstancedMesh` уже даёт один draw call на все чаинки. Если тормозит, порядок
подкрутки: `dpr` в `<Canvas>` (сейчас `[1, 1.75]`) → `shadow-mapSize` (1024) →
`LEAF_COUNT` (220) → `resolution` у `ContactShadows`.

### Утечки памяти

Каждая созданная геометрия/материал/текстура требует `dispose()`. Схема:

- **текстуры** — кеш модуля, освобождаются через `disposeConstructorTextures()`
  при размонтировании `ThreeScene`;
- **материалы** — свои у каждого экземпляра, освобождаются через
  `disposeMaterial()` в cleanup компонента;
- **геометрии** — в `useMemo` + `useEffect(() => () => geo.dispose(), [geo])`.

`material.dispose()` **не** освобождает текстуры материала — поэтому и нужен
`disposeMaterial()`.

## 9. Текущий рабочий поток

### Файлы и режимы

`ConstructorPage` проверяет вход. `ConstructorChoice` сначала показывает коробки в 3D
(`ConstructorBoxScene`, исходная модель `GiftBox` и размерные линии по X/Z), затем
две компактные карточки «С анимацией / Вручную». Размеры не привязаны к режимам:
`advanced/options` отдаёт все активные коробки с `simple_requirements`; доступность
анимационного режима определяется этими настройками. При двух коробках API в сцене
видны две модели; фиктивный второй размер не добавляется. Под сценой остаются
доступные с клавиатуры кнопки с названием и размерами из API. Форматы загружаются
только после явного выбора коробки, без мокового fallback.
`ConstructorEditor` хранит состав/координаты, `GiftConfirmation` обслуживает общий
pipeline до корзины. Стили: `ConstructorWorkspace.module.scss`.

`ConstructorSteps` показывает «Коробка → Способ сборки → Наполнение → Проверка → Корзина».
Стрелка назад и пройденные шаги доступны также во время загрузки товаров.
Возврат к уже пройденному шагу сохраняет состав той же коробки; возврат из
проверки отменяет старый quote, следующий вход получает свежую цену. После
создания Gift возврат заблокирован, чтобы не потерять его ID и UUID операции cart.
Шаг «Корзина» не означает оформленный заказ: доставка и checkout идут отдельно.
Выбор другой коробки очищает состав. Возврат к той же коробке и смена способа
сохраняют отдельные simple/advanced-черновики без повторного GET товаров.
Скрытая сцена размонтируется, черновик остаётся в редакторе.
Смена пользователя размонтирует всё рабочее пространство.

`ConstructorCarousel` сложного режима показывает вкладки «Чай / Сладости / Другое»
строго по `ProductSize.constructor_role`: `tea / sweet / general`. Внутри вкладки —
страницы по 12 форматов (4×3 на широком экране), поиск и лента без зацикливания.
Ширина рабочей области — `max-width(full)` из общего SCSS (1994px), большая часть отдана каталогу. Карточки ниже,
кнопки заменены на MUI `AddShoppingCartRounded` и `VisibilityOutlined` с aria-label/title.
Число колонок адаптируется; внеэкранные страницы помечены inert и aria-hidden.
Стеклянные стрелки стоят в отдельных боковых полях и не перекрывают карточки;
снизу остаётся только приглушённый номер страницы. В простом списке используются
кнопки номеров страниц без нижних стрелок «Назад / Далее».
Клавиши ←/→, Home/End работают на вкладках и сетке.
`ConstructorEditor` хранит вкладку, поиск и ID последнего формата каждого типа:
возврат к коробке/из проверки не сбрасывает их. Это память текущего редактора,
не сохранение черновика после перезагрузки. При исчезновении формата показывается
первый доступный; пустой результат объясняется текстом, без моков.
Категории вроде «кофе» не выдумываются: более глубокую иерархию должен отдать API.

| Режим | Выбор | Проверка |
|---|---|---|
| Простой | Списки чая и сладостей с кнопками +/− | Число позиций из `simple_requirements`, без ограничения 2+1; размещает сервер |
| Сложный | Сетка фактических `width_cells × height_cells` | Границы, поворот и пересечения локально; окончательная проверка на сервере |

Оба режима работают с `product_size.id`, а не `product.id`. `product_quantity`
измеряется в `gram` или `piece`; цена компонента показана до скидок, финальная
цена берётся только из quote. Список совместимых форматов не гарантирует остаток
и возможность уложить весь выбранный набор: это дополнительно проверяет backend.

### Камера и раскладка

`SimplePackingScene` возвращает исходные `TeaSachet`, `SweetItem`, `LeafParticles`:
чай открывается, наполняется и ложится в коробку; сладость заворачивается и перевязывается.
Количество берётся из `simple_requirements`, а не из старой жёсткой схемы 2+1.
Быстрые клики сразу меняют состав, визуальная упаковка идёт по очереди. Анимация
декоративная: раскладку simple считает сервер; из завершения анимации POST не вызывается.
Уже упакованные предметы не проигрываются заново при возврате; reduced motion пропускает движение.

`BoxFloorScene` подгружается лениво в ручном режиме и использует исходный
`three/GiftBox`. В режиме «Обзор» разрешён ручной поворот вокруг вертикальной оси Y в пределах
±36° горизонтальным Pointer Events-жестом или кнопками. Автокручения нет;
вертикальный жест остаётся прокруткой страницы. После drag модель не выбирается
случайным click. Есть кнопка возврата к исходному ракурсу.
После выбора «Вручную» камера автоматически за ~0,8 с переходит к виду сверху,
без повторного выбора коробки. Кнопки «Сверху / Обзор» переключают редактирование
и осмотр объёмных моделей чая/сладостей. Под ними остаётся тот же экземпляр GiftBox;
крышка, лента и бант убраны, чтобы не перекрывать дно. Ручной ракурс плавно
возвращается к нулю; во время расстановки вращение отключено, чтобы не конфликтовать
с переносом предметов. `prefers-reduced-motion` пропускает движение,
но не выбор способа сборки. При смене коробки способ выбирается заново.

Внутренняя область модели масштабируется под реальные ячейки коробки с учётом
толщины стенок. Сетка рисуется линиями над текстурным дном. После остановки камеры
над ним появляется DOM-слой `FloorGrid`: его масштаб вычисляется той же функцией
`floorViewport`, что и zoom ортографической камеры. ResizeObserver обновляет слой
при изменении размера. Этот же компонент работает без WebGL.

`useConstructorDrag` отвечает за перенос **всей карточки**, без отдельной ручки,
и предметов внутри коробки. Мышь, перо и предметы на дне используют Pointer Events.
На touch-карточке удержание 400 мс включает перенос, быстрый горизонтальный жест
листит карусель, вертикальный до удержания остаётся нативной прокруткой страницы.
Вложенная кнопка «Добавить» не запускает drag. При лимите добавление запрещено,
но карусель можно продолжать просматривать. Touch-обработчики отменяют прокрутку
только для выбранного жеста; второй палец, touchcancel и Escape отменяют удержание.
Хук сохраняет точку захвата предмета на дне, привязывает к целой сетке
и показывает footprint: зелёный для допустимого положения, красный для коллизии
или выхода за границы. Координаты меняются только при допустимом pointerup.
Escape, pointercancel, потеря capture/фокуса и скрытие вкладки отменяют жест.
Все обработчики, таймер удержания и capture освобождаются при размонтировании;
API из жестов не вызывается. У края экрана во время переноса включается
автопрокрутка до 480 px/с; цикл прекращается по окончании жеста, на границе
документа, при скрытии вкладки и размонтировании. `ProductTexture` показывает только
изображение товара, без названия и габаритов. Над дном остаётся один preview реального
размера; вне дна — компактная текстура у курсора. Статус переноса оставлен для скринридера,
а на экране видна только тонкая зелёная/красная граница.
Нативные изображения не перетаскиваются, внешние drag payload не принимаются.

Карточка показывает геометрический след в маленькой SVG-схеме дна: сетку коробки,
закрашенный прямоугольник без числовой подписи в compact-режиме. Длинного
текстового описания footprint на карточке нет. «Подробнее» тоже остаётся компактным:
изображение, формат, количество, цена и та же схема, без полного описания товара.
Это **не** объём, остаток или гарантия вместимости.
Фокус/нажатие на предмет выбирает его: появляется рамка с маркерами и ручкой
поворота, а в заголовке — иконки ↶/↷ и удаления. `useItemRotation` принимает
Pointer Events и фиксирует четверть-оборот только на pointerup, через ту же
проверку границ/пересечений. Escape, pointercancel, blur и размонтирование отменяют
поворот. API по-прежнему хранит boolean `is_rotated`, произвольных углов нет.
Поля «Позиция / Столбец / Строка» и дублирующий список убраны. Перемещение доступно
стрелками клавиатуры, поворот — R, удаление — Delete/Backspace. Подписи размеров
сохраняются только в доступном имени предмета, а не поверх текстуры.
Оба поворота на 90° проверяют `can_rotate`, границы и пересечения до изменения state.
Backend хранит только `is_rotated`: +90° и −90° одинаково меняют ширину/высоту
прямоугольного следа. Отдельная ориентация этикетки на 180°/270° не сохраняется.
В простом режиме списки и 3D-анимация стоят рядом; drag не нужен.

Для ручной проверки на телефоне: свайпнуть карточку в обе стороны, прокрутить
страницу вертикально, удержать и перенести к дну с автоскроллом, отменить жест,
повернуть предмет у стенки/соседа. jsdom проверяет события и геометрию, но не
заменяет эту проверку нативных жестов Safari/Chrome и совмещения с WebGL.

Подписи размеров показываются в клетках и дополнительно в мм только при наличии
положительного `cell_size_mm` из API. Значение 10 мм автоматически не предполагается.
Это размер footprint формата, не вес содержимого. Иконка корзины, выбор ячейки,
стрелки клавиатуры и поворот 90° — доступная альтернатива drag-and-drop.

Бант исходной GiftBox теперь собран из широких ленточных поверхностей с толщиной,
приподнятыми петлями и V-образными хвостами (`three/bowGeometry.ts`). Геометрия
создаётся один раз на экземпляр и освобождается вместе с моделью; новых ассетов
или сетевых загрузок нет.

Добавленный иконкой корзины формат занимает первое свободное место. Выберите позицию, затем
ячейку для её верхнего левого угла, либо используйте drag/стрелки.
Координаты в API начинаются с 0. Поворот 90° разрешён только при `can_rotate`.
Это редактор прямоугольных footprint, не физическая симуляция упаковки.

Canvas использует `frameloop="demand"`, DPR ограничен 1,5: после перехода нет
постоянного цикла анимации. Это уменьшает нагрузку, но не означает нулевой расход
батареи. В скрытой вкладке `frameloop="never"`; общий кеш текстур освобождается
после ухода последней сцены, а не при переключении каждой отдельной модели.
WebGL не обязателен: кнопка отключения 3D и fallback при потере контекста
сохраняют редактирование. Для сеток >1600 ячеек показывается предложение выбрать
меньшую коробку, без создания тысяч DOM/WebGL объектов.

### Контракты (backend только прочитан, не изменён)

| Действие | API |
|---|---|
| Коробки | `GET /api/gift-constructor/{simple|advanced}/options` |
| Совместимые форматы коробки | `GET /api/gift-constructor/boxes/{id}/products` |
| Проверка координат сложного режима | `POST /api/gift-constructor/advanced/validate-layout` |
| Цена, наличие, раскладка | `POST /api/gift-constructor/{simple|advanced}/quote` |
| Создание приватного Gift после нажатия | `POST /api/gift-constructor/{simple|advanced}/gifts` |
| Добавление одной строки подарка | `POST /api/cart/gifts` |

В quote передаётся `quantity: 1`, при создании — название и состав. В cart:
`gift_id`, `gift_version`, `quantity: 1`, стабильный `client_instance_id` UUID.
Никаких запросов записи из callbacks анимации. Повтор после сбоя cart использует
тот же Gift и UUID. Backend создания Gift не поддерживает idempotency: после
неопределённого исхода (timeout/5xx) автоматический и ручной повтор создания
на этом экране блокируется. Нельзя гарантировать восстановление такого результата
после перезагрузки страницы без доработки backend.

### Если данные не загрузились

1. Проверить вход: options требует авторизации. `401` — сессия, `403` — доступ.
2. В Network проверить `/options` и `/boxes/{id}/products`: статус, JSON,
   наличие `boxes`/`product_sizes`, а не HTML от fallback frontend. Проверить proxy `/api`.
3. Проверить активность коробки, её `simple_constructor_enabled` и требования,
   активные ProductSize с нужной ролью и габаритами. Пустой список отображается явно.
4. `404` — сверить backend/ID; `429` — подождать; при сетевом сбое нажать повтор.

Пустой успешный `/boxes/{id}/products` теперь сопровождается диагностикой.
`loadOptions` сохраняет общий список ProductSize, чтобы сравнить ответы:

- 0 в options и 0 для коробки: API не отдал доступных форматов этого режима.
  Это не доказывает пустоту таблицы: также проверяются активность ProductSize,
  активный профиль `kind=item`, доступность товара и роли для простого режима.
- В options форматы есть, для коробки 0: проверить размеры/поворот, предел веса
  и `product_quantity`, которое должно соответствовать `sale_step` товара.
- Отсутствующее поле массива или HTML вместо JSON — ошибка контракта, не пустой список.

В проверенной версии `DatabaseSeeder` вызывает `ProductSeeder` и
`GiftSizeProfileSeeder`, но ни один из сидеров не создаёт записи `product_sizes`.
После стандартной инициализации коробки могут существовать без форматов товаров.
Нужны реальные связи `product_id`, `gift_size_profile_id`, `product_quantity`,
`constructor_role`, `is_active`. Их создание требует отдельной backend-задачи;
этот frontend-патч не изменяет БД и не подставляет ID обычного товара вместо ProductSize.
Общий каталог options не используется как fallback для отвергнутых коробкой форматов.
Кнопка «Обновить каталог конструктора» повторяет оба чтения без сброса выбранной коробки.

GET и расчёт отменяются при смене коробки/режима/аккаунта. Старый ответ не
принимается, даже если транспорт проигнорировал AbortSignal. Timeout запросов
конструктора — 15 с. Нет fallback на моки. Offline сохраняется только текущий
выбор в памяти вкладки; после reconnect выполняется чтение, но не запись.
Смена коробки/режима сбрасывает выбор, смена аккаунта размонтирует workspace.

Точная причина сбоя на конкретном устройстве определяется по его Network-логу.
Найденные в прежнем frontend ограничения 2+1 и зависимость от WebGL устранены;
это не подтверждение исправности развёрнутого backend или его proxy.

### Проверки

`npm run test:constructor`, `npm run test:offline`, `npm run typecheck`,
`npm test`, `npm run build`.
Если предыдущий патч применён без изменения package.json, достаточно `npm test`:
все новые тесты входят в обычный запуск, новые npm scripts не обязательны.

Тесты проверяют список 5+2, advanced payload, коллизии/границы/повороты,
отмену устаревших загрузок, ошибки авторизации, offline/reconnect, повтор cart с
тем же UUID, двойной клик, смену аккаунта и вывод серверной ошибки как текста
(включая SVG/XSS payload). В DOM-тестах Three.js заменён плоской сеткой;
они не подтверждают реальный рендер WebGL или плавность камеры.
Дополнительно проверяются перенос из каталога без дубля, перенос существующего
предмета, коллизии, отмена/потеря capture, возврат по шагам, группировка, размеры,
пределы камеры и корректность вершин/индексов ленточной геометрии.

Ручной smoke: оценить бант в предпросмотре, повернуть коробку мышью/пальцем и кнопками,
подтвердить выбор, дождаться фиксации вида сверху. Перетащить формат из каталога,
передвинуть внутри коробки, проверить красную/зелёную подсветку, Escape и отпускание
за пределами сетки. Повторить на телефоне и в плоском режиме; проверить resize,
reduced-motion, возврат по шагам, Network Offline и добавление реального Gift в корзину.
