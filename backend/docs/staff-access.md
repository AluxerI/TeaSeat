# Сотрудники: роли и рабочие точки

## Принятые правила

- Один аккаунт может одновременно иметь роли `seller`, `courier` и `manager`.
- Основной рабочей точки нет. У сотрудника может быть несколько активных точек.
- `user_warehouse.is_active` означает, что сотрудник сейчас может работать на точке.
- При переводе сотрудника старая связь не удаляется, а становится неактивной. Это сохраняет историю.
- Менеджер пока имеет глобальный доступ к заказам. Связь с точками оставлена для будущих зон ответственности.

## Роли

| Роль | Назначение |
| --- | --- |
| `admin` | Полный административный доступ |
| `manager` | Заказы, склад, проблемы комплектации и назначение курьеров |
| `seller` | Создание, просмотр и завершение своих продаж |
| `courier` | Просмотр и обновление назначенных доставок |
| `user` | Обычный покупатель |

Роли и права создаются идемпотентно: `RolePermissionSeeder` можно запускать повторно.

## Контракт API пользователя

`POST /api/auth/login`, `POST /api/auth/register` и `GET /api/user` возвращают одинаковый контекс:

```json
{
  "roles": ["seller", "courier", "manager"],
  "work_locations": [
    {
      "id": 4,
      "name": "Магазин Тула Южный",
      "city": "Тула",
      "type": "store",
      "is_online_fulfillment_enabled": true
    }
  ],
  "capabilities": {
    "admin": false,
    "manager": true,
    "seller": true,
    "courier": true,
    "can_access_filament": true
  }
}
```

Фронтенд строит навигацию по `capabilities`, но бекенд всё равно проверяет каждое право. Скрытие кнопки не считается авторизацией.

В ответе входа `token` — строка Sanctum, а `token_type` равен `Bearer`.

## Безопасность

- Заблокированный `users.is_active = false` не может войти.
- При блокировке аккаунта его текущие Sanctum-токены и веб-сессии удаляются.
- Filament доступен только активным `admin` и `manager`.
- `seller`, `courier` и `user` не могут открыть Filament, даже если знают его URL.
- Неактивные точки не возвращаются в PWA-контексте и не могут быть назначены заново.

## Первый запуск

Так как связующая таблица добавлена в существующую миграцию складов, в разработке нужен `php artisan migrate:fresh --seed`. Команда удалит текущие тестовые данны.
