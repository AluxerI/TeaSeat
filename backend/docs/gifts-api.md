# API подарков TeaSeat

## Модель первой версии

- Пользовательский подарок (`gifts`) — приватная конфигурация. Собственного складского остатка у неё нет.
- Каждый компонент пользовательского подарка резервируется как обычный товар. На checkout одинаковые SKU из обычных строк и всех подарков суммируются.
- Наценка коробки и сборки берётся с сервера из профиля коробки. Клиент не передаёт и не изменяет её.
- Готовый подарок магазина — обычный `product` с `product_type=preassembled_gift` и собственным остатком.
- `assembly_instructions` готового подарка является внутренним полем: публичный каталог его не отдаёт, API сборщика отдаёт.
- Размер сетки задаётся в `config/gifts.php`; фронтенд получает `cell_size_mm` из options API.

Все клиентские маршруты требуют Sanctum-токен пользователя.

## Каталог для выбранной коробки

### `GET /api/gift-constructor/boxes/{box}/products`

Возвращает коробку и полный список активных `product_sizes`, каждый из которых
можно отдельно разместить в выбранной коробке. Пагинации нет.

```json
{
  "data": {
    "box": {
      "id": 4,
      "name": "Маленький подарочный набор",
      "simple_requirements": {
        "tea_count": 2,
        "sweet_count": 1
      }
    },
    "product_sizes": []
  }
}
```

Проверяется активность товара, записи `product_sizes`, профиля размера,
кратность складского количества, габариты, допустимый поворот и ограничение
веса коробки для одной позиции. Полная совместимость нескольких выбранных
товаров и актуальный остаток проверяются маршрутами validate/quote.

Frontend выбирает `product_size_id`, а не только `product_id`: одна запись
одновременно определяет товар, количество товара и занимаемый размер.
В простом конструкторе из этого каталога используются позиции с ролями `tea`
и `sweet`; сложный конструктор может использовать также роль `general`.

## Сложный конструктор

### `GET /api/gift-constructor/advanced/options`

Возвращает активные коробки и форматы товаров. Товар виден в конструкторе только при наличии активной записи `product_sizes`.

### `POST /api/gift-constructor/advanced/validate-layout`

```json
{
  "box_profile_id": 5,
  "items": [
    {
      "client_item_id": "4f4fd30e-4055-4dc8-819c-1dd31dd68aa6",
      "product_size_id": 17,
      "position_x": 0,
      "position_y": 0,
      "is_rotated": false
    }
  ]
}
```

Проверяет границы, пересечения, разрешение поворота, максимальный вес и доступность форматов. Координаты считаются от нуля.

### `POST /api/gift-constructor/advanced/quote`

Тело совпадает с validate; дополнительно можно передать `quantity`, `city` и `discount_selection` в том же формате, что у `/api/cart/quote`. Возвращает раскладку, требуемое количество каждого SKU и серверный pricing quote. Quote не резервирует товар.

### `POST /api/gift-constructor/advanced/gifts`

Тело совпадает с validate и содержит обязательное `name`, необязательное `description`. Создаёт приватный подарок и возвращает версию. Клиент обязан сохранить `id` и `version`.

## Простой конструктор

Простой API использует тот же grid-движок и автоматически размещает товары.

### `GET /api/gift-constructor/simple/options`

Возвращает только коробки, включённые для простого конструктора,
`tea_product_sizes` и `sweet_product_sizes`. Каждая коробка содержит собственные
требования:

```json
{
  "id": 4,
  "name": "Маленький подарочный набор",
  "simple_constructor_enabled": true,
  "simple_requirements": {
    "tea_count": 2,
    "sweet_count": 1,
    "total_items": 3,
    "allow_duplicate_products": true
  }
}
```

В стандартном наполнении маленькая коробка требует два чая и одну сладость,
большая — пять чаёв и две сладости. Эти числа управляются из Filament и не
зашиты в контроллер.

### `POST /api/gift-constructor/simple/quote`
### `POST /api/gift-constructor/simple/gifts`

```json
{
  "box_profile_id": 4,
  "name": "Чайный вечер",
  "tea_product_size_ids": [11, 15],
  "sweet_product_size_ids": [27],
  "quantity": 1,
  "city": "Москва"
}
```

Количество элементов в массивах должно совпадать с `simple_requirements`
выбранной коробки. Один `product_size_id` можно повторять: каждый повтор станет
отдельной позицией раскладки, а одинаковые SKU будут суммированы при проверке и
резервировании остатка. `name` нужен только при создании, `quantity` — только
для quote.

## Приватные подарки пользователя

- `GET /api/gifts`
- `GET /api/gifts/{gift}`
- `PUT /api/gifts/{gift}` — полное обновление в формате сложного конструктора; версия увеличивается.
- `DELETE /api/gifts/{gift}` — архивирование, а не физическое удаление.

Пользователь имеет доступ только к собственным подаркам. Уже добавленная в корзину версия хранится снимком и не меняется при последующем редактировании шаблона.

## Корзина

### `POST /api/cart/gifts`

```json
{
  "gift_id": 42,
  "gift_version": 3,
  "quantity": 2,
  "client_instance_id": "4aa2d299-6935-47ea-bd03-21a2ce88bbb4",
  "city": "Москва"
}
```

`client_instance_id` обеспечивает идемпотентность добавления. При повторе UUID тело должно совпадать. Если версия устарела, сервер возвращает 422.

- `PUT /api/cart/gifts/{orderGift}` — `{ "quantity": 3, "city": "Москва" }`.
- `DELETE /api/cart/gifts/{orderGift}`.

Компоненты нельзя изменять старыми маршрутами `/cart/update/{itemId}` и `/cart/remove/{itemId}`. В `CartResource` обычные строки находятся в `items`, наборы — в `gifts[].items`.

На checkout сервер повторно рассчитывает цену и под блокировкой резервирует агрегированное количество всех SKU. Акции на товары применяются к компонентам; cart-скидка рассчитывается от суммы компонентов и наценки.

## Готовые подарки и сборщик

Маршруты требуют роль/права сборщика и ограничены назначенными активными точками.

### `GET /api/picker/assembled-gifts?warehouse_id=1`

Возвращает готовые SKU, внутреннюю инструкцию и остатки доступных сборщику точек.

### `POST /api/picker/assembled-gifts/{product}/replenish`

```json
{
  "warehouse_id": 1,
  "quantity": 5,
  "idempotency_key": "bd7a0fa9-b76b-488e-a127-126a06d700ea",
  "comment": "Смена 15 июля",
  "consumed_items": [
    { "product_id": 10, "quantity": 5 },
    { "product_id": 11, "quantity": 10 }
  ]
}
```

Сервер не хранит BOM готового подарка: сборщик сообщает фактически использованные товары. В одной транзакции свободный физический остаток компонентов уменьшается, остаток готового SKU увеличивается, а `inventory_movements` получает `gift_assembly_consume` и `gift_assembly_produce`. Резерв интернет-магазина и продавца расходовать нельзя. Повтор одного UUID не применяет движение второй раз.

## Ошибки

- `401` — отсутствует/истёк токен.
- `403` — нет роли или доступа к складу.
- `404` — сущность не найдена либо не принадлежит пользователю.
- `422 gift_configuration_invalid` — неверная раскладка или правило конструктора.
- `422 gift_cart_rejected` — устаревшая версия, недостаток товара или конфликт UUID.
- `422 gift_assembly_rejected` — неверный готовый SKU или недостаток свободных компонентов.
