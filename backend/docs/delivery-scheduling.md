# Календарь и интервалы доставки

## Правила первой версии

- Расписание относится к способу доставки и одинаково для всех его городов.
- Календарь обязателен для `courier` и `express`; `pickup` и `external` его не
  используют.
- Покупатель видит 30 календарных дней вперёд с учётом минимального срока
  конкретного способа доставки.
- У каждого повторяющегося недельного интервала есть вместимость — число
  клиентских заказов. Порядок поездок внутри интервала определяет курьер.
- Отменённые заказы освобождают место автоматически.
- Время и вместимость редактируются в Filament в разделе
  «Заказы → Интервалы доставки». Отключённый интервал не предлагается новым
  покупателям, но снимок старого заказа сохраняется.

Горизонт и окно курьера задаются переменными
`DELIVERY_BOOKING_HORIZON_DAYS` и `COURIER_CLAIM_LEAD_HOURS`.
Даты и часы первой версии трактуются в `APP_TIMEZONE` приложения.

## Поток frontend

1. Получить способы доставки существующим маршрутом
   `GET /api/checkout/delivery-methods/{addressId}`.
2. Если у способа `requires_scheduling=true`, запросить:

   `GET /api/checkout/delivery-slots/{addressId}/{deliveryMethodId}`

3. Показать только элементы `dates[].slots[]`, возвращённые backend.
4. Передать выбранные значения в существующий checkout:

```json
{
  "shipping_address_id": 8,
  "delivery_method_id": 2,
  "scheduled_delivery_date": "2026-08-19",
  "delivery_time_slot_id": 12,
  "payment_method": "card"
}
```

Frontend не рассчитывает вместимость и не передаёт собственные `time_from` /
`time_to`. Backend повторно проверяет выбор в транзакции checkout и сохраняет
снимок интервала в заказе. Поэтому изменение будущего расписания не меняет уже
обещанное клиенту время.

Пример ответа календаря:

```json
{
  "data": {
    "delivery_method": {"id": 2, "name": "Курьер", "type": "courier"},
    "booking_horizon_days": 30,
    "dates": [{
      "date": "2026-08-19",
      "weekday": 3,
      "slots": [{
        "id": 12,
        "time_from": "10:00",
        "time_to": "14:00",
        "capacity": 5,
        "booked": 2,
        "remaining_capacity": 3
      }]
    }]
  }
}
```

Пустой `dates` означает, что в доступном горизонте свободных интервалов нет.
При гонке двух checkout последний свободный слот получает только один заказ;
второй запрос получает `422` и должен обновить календарь.

## Курьер

Клиентский заказ появляется в свободном `GET /api/courier/deliveries` только
за 24 часа до `scheduled_window.time_from`. Уже назначенный курьер продолжает
видеть свой заказ. Это ограничение не применяется к межскладским перемещениям.

Отказ до начала доставки:

`POST /api/courier/deliveries/{order}/release`

```json
{"reason":"Не смогу выйти на смену"}
```

Причина обязательна. Назначение очищается, заказ возвращается в очередь, а
действие остаётся в `internal_notes`.

## Менеджер

Перенос выполняется маршрутом
`POST /api/manager/orders/{order}/reschedule`; контракт и ограничения описаны
в `docs/manager-orders.md`. Ресурсы клиента, менеджера и курьера возвращают
`scheduled_window` из сохранённого снимка заказа.
