# Обращения клиента по заказу

Обращение сообщает менеджеру о требуемом действии, но само не изменяет заказ.
Состав оформленного заказа клиент через этот API не редактирует: для нового
состава заказ отменяется и создаётся заново.

## Типы

- `change_delivery` — вопрос об изменении доставки;
- `cancel_order` — запрос отмены, когда обычная отмена уже недоступна;
- `order_problem` — проблема с заказом, комментарий обязателен;
- `other` — другая ситуация, комментарий обязателен.

По одному заказу одновременно допускается одно открытое обращение каждого типа.
Заказы `cart`, `cancelled` и `completed` обращения не принимают. Для
`delivered` доступны только `order_problem` и `other`.

## Клиент

- `GET /api/orders/{order}/requests` — история своих обращений;
- `POST /api/orders/{order}/requests` — создать обращение;
- `POST /api/order-requests/{orderRequest}/withdraw` — отозвать обращение в
  статусе `waiting`.

Пример:

```json
{
  "type": "other",
  "message": "Позвоните, пожалуйста, перед въездом во двор"
}
```

Отзыв сохраняется в истории со статусом `withdrawn`.

## Менеджер

- `GET /api/manager/order-requests` — очередь с фильтрами `status`, `type`,
  `order_id`, `mine`, `per_page`;
- `GET /api/manager/order-requests/{id}` — карточка;
- `POST .../{id}/take` — взять в работу;
- `POST .../{id}/release` — вернуть своё обращение в очередь;
- `POST .../{id}/resolve` — завершить;
- `POST .../{id}/reject` — отклонить.

Завершение и отклонение требуют:

```json
{
  "manager_comment": "Результат обработки, который увидит клиент"
}
```

Менеджер видит только заказы назначенных ему активных складов; администратор —
все. Взять уже занятое обращение или завершить чужое нельзя. Состояния:
`waiting`, `in_review`, `resolved`, `rejected`, `withdrawn`.
